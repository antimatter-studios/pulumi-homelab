- `provider/safeops`: one shared way for a delete to remove an entry only while it is still exactly what a resource made, and the digests it checks against. It pins the parent and captures the entry with `renameat2(RENAME_NOREPLACE)` into a private directory. It verifies the entry there: a symlink's exact target, a file's or tree's sha256 computed without following links or crossing mounts. It then removes the entry, or puts it back without replacing anything. Anything kept, partly removed or left behind is reported with where it is. It runs as a perl script (perl-base is Essential on Debian) and refuses without perl. `provider/RULES.md` holds the rules every Go resource follows. It also installs a file without replacing anybody else's: on create, what is there is moved aside and kept, and the file goes in with `link(2)`; on update, `rename(2)` replaces it. And it resolves a path's physical parent for a resource to record at Create (`/lib/x` is recorded as `/usr/lib/x`). Digests come from coreutils `sha256sum` reading a descriptor the script opened without following links (`perl-base` has no `Digest::SHA`), and a machine without `sha256sum` is refused.
