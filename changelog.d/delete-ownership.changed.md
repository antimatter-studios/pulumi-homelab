- Deletes remove only what the resource can prove it made. When it cannot prove it (no recorded digest, the object changed since the provider wrote it, or it is not the expected kind of object), the delete logs a warning naming the path and the reason, leaves the object on the machine, and succeeds, so Pulumi drops the resource from state. This applies to ManagedFile, ProtectedFile, SshTunnel units, Archive prefixes, Samba shares and accounts, and GitCheckout paths with uncommitted or unpushed work.
- For every resource that was imported rather than created by the provider (most of those in a stack that switched from the TypeScript library), removing it from the program now leaves its file, unit or share on the machine with a warning instead of deleting it. To really remove one, delete it by hand, or let the provider rewrite it first (an update that writes it records a digest), then remove it from the program.
- Also: Symlink deletes are race-free, ManagedLine matches its marker exactly, a failed AuthorizedKey read fails instead of rewriting the file, and an SshKey type change on the same path no longer deletes the new pair.
